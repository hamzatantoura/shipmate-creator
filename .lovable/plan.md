# المشكلة

عند إنشاء طلب جديد، التاجر يرى **بطاقة واحدة فقط لكل شركة شحن** تحتوي على "أقرب فرع" — مع أن مسارات لديها 5 فروع نشطة في اللاذقية (وغيرها). التاجر لا يستطيع اختيار فرع آخر غير الذي يقترحه النظام تلقائياً.

## السبب التقني

دالة `find_couriers_for_order` في قاعدة البيانات تستخدم `WHERE r.rn = 1` — أي تُرجع صفاً واحداً لكل شركة (الأقرب جغرافياً فقط). الفروع الأخرى تُحسب فقط في عدّاد `total_branches_in_destination` بدون تفاصيلها.

النتيجة: التاجر يرى "(5 فروع متاحة في المحافظة)" لكن لا يستطيع تصفح الـ 4 الأخرى.

# الحل المقترح

## 1) تعديل دالة قاعدة البيانات

إضافة دالة جديدة `list_courier_branches_for_order` تُرجع **كل الفروع النشطة لشركة معينة في محافظة الزبون**، مرتبة بالأقرب جغرافياً، مع المسافة لكل فرع. الدالة الأصلية تبقى كما هي لاستخدامها في عرض البطاقات الرئيسية.

```sql
CREATE OR REPLACE FUNCTION public.list_courier_branches_for_order(
  p_courier_id uuid,
  p_customer_province_id uuid,
  p_customer_lat double precision DEFAULT NULL,
  p_customer_lng double precision DEFAULT NULL
) RETURNS TABLE (
  branch_id uuid,
  branch_name text,
  address_details text,
  phone text,
  lat double precision,
  lng double precision,
  distance_km double precision
) ...
-- ترجع كل الفروع النشطة (بدون LIMIT)
```

## 2) تعديل واجهة إنشاء الطلب (`MerchantOrdersPage.tsx`)

تحويل بطاقة شركة الشحن إلى عنصر **قابل للتوسع** (Collapsible/Accordion):

- البطاقة الافتراضية تعرض الشركة + الفرع الأقرب + السعر (كما هي الآن)
- زر "عرض كل الفروع (5)" يفتح قائمة بكل الفروع
- التاجر يختار الفرع الذي يريده مباشرة
- الفرع المختار يُحفظ في `form` كـ `branchId` بالإضافة إلى `courierId`

```text
┌─ مسارات                                      18,000 ل.س ┐
│  📍 مسارات - جبلة · 12.3 كم            ⭐ الأقرب         │
│  ▼ عرض كل الفروع (5)                                    │
│     ○ مسارات - اللاذقية المركز · 2.1 كم    18,000 ل.س   │
│     ● مسارات - جبلة · 12.3 كم              18,000 ل.س   │
│     ○ مسارات - القرداحة · 18.7 كم          18,000 ل.س   │
│     ○ مسارات - الحفة · 24.5 كم             18,000 ل.س   │
│     ○ مسارات - صلنفة · 35.1 كم             18,000 ل.س   │
└──────────────────────────────────────────────────────────┘
```

## 3) حفظ الفرع المختار في الطلب

- إضافة عمود `pickup_branch_id uuid REFERENCES courier_branches(id)` على جدول `orders` (إذا غير موجود).
- عند إنشاء الطلب، حفظ `pickup_branch_id` بالإضافة لـ `courier_id`.
- إذا لم يختر التاجر فرعاً صراحة، يُحفظ الفرع الأقرب تلقائياً (سلوك حالي).

## 4) تطبيق نفس التحسين على

- `EditOrderDialog.tsx` (تعديل طلب موجود) — نفس آلية اختيار الفرع.

# ملاحظات

- ترتيب الفروع داخل القائمة الموسعة بالمسافة (الأقرب أولاً) إذا توفرت إحداثيات؛ وإلا أبجدياً.
- السعر لكل فرع يُحسب من `courier_district_rates` (نفس المنطق الحالي) — السعر يعتمد على المنطقة لا على الفرع، لذلك يكون موحداً عادةً.
- لن تتغير قائمة الشركات الظاهرة، فقط ستضاف إمكانية تصفح فروع كل شركة.
