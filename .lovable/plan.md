# خطة: إعدادات سياسات شركات الشحن (مركزية بيد الأدمن)

## الهدف
كل شركة شحن لها سياساتها الخاصة (رسوم تحصيل COD، رسوم الإرجاع، عدد محاولات التسليم، مهلة التسليم) يضبطها **الأدمن فقط** من داخل ملف الشركة. هذه القيم تُستخدم تلقائياً في:
- حساب أجرة الشحن التي يراها التاجر
- حساب مستحقات شركة الشحن
- منطق الإرجاع وخصم الرسوم
- عرض السياسة للتاجر قبل اختيار الشركة

---

## 1) تعديل قاعدة البيانات (جدول `couriers`)

الحقول الموجودة فعلاً:
- `cod_fee_type` (percentage | fixed) ✅
- `cod_fee_value` ✅
- `return_fee_percentage` ✅

الحقول المطلوب إضافتها:
- `return_fee_type` نص (`percentage` | `fixed`) — افتراضي `percentage`
- `return_fee_fixed` رقم — افتراضي 0 (يُستخدم عند `type=fixed`)
- `max_delivery_attempts` عدد صحيح — افتراضي 3
- `delivery_sla_hours` عدد صحيح — مهلة التسليم بالساعات، افتراضي 72
- `cod_collection_responsibility` نص (`merchant` | `courier_absorbs`) — من يدفع رسم التحصيل، افتراضي `merchant`
- `policy_notes` نص — ملاحظات حرة من الأدمن تظهر للتاجر

**الصلاحيات:** التعديل للأدمن فقط (سياسات RLS الحالية كافية). القراءة متاحة لكل المصادَقين عبر سياسة `Authenticated can view active couriers minimal`.

---

## 2) واجهة الأدمن — `AdminCouriersManagement`

داخل نموذج تحرير شركة الشحن، إضافة قسم جديد **"السياسات والرسوم"** بثلاث بطاقات:

**أ) رسوم تحصيل المبلغ النقدي (COD)**
- نوع الرسم: نسبة % / مبلغ ثابت (Select)
- القيمة (Input رقمي)
- من يتحملها: التاجر / الشركة تتحملها (Select)

**ب) سياسة الإرجاع**
- نوع الرسم: نسبة من أجرة الشحن / مبلغ ثابت (Select)
- القيمة (Input رقمي)

**ج) التسليم**
- عدد المحاولات قبل اعتبارها مرتجعة (Input 1-5)
- مهلة التسليم بالساعات (Input)
- ملاحظات السياسة (Textarea — تظهر للتاجر)

كل التغييرات تُسجّل في `field_audit_logs` تلقائياً.

---

## 3) محرك التسعير — `src/features/wallet/lib/pricing-engine.ts`

دالة موحّدة تأخذ `courier` + `order_value` + `shipping_base_fee` وتُرجع كائناً كاملاً:

```text
{
  courier_fee:           أجرة الشركة الأساسية (من courier_district_rates)
  cod_fee:               حسب cod_fee_type/value
  cod_fee_payer:         merchant | courier
  platform_margin:       هامش المنصة
  merchant_total:        ما يدفعه/يخصم من التاجر
  courier_payout:        ما يستحقه السائق (= courier_fee + cod_fee إذا التاجر يدفعها)
  return_fee_calc(amt):  دالة لحساب رسم الإرجاع عند الحاجة
}
```

**مصدر واحد للحقيقة** — كل الواجهات تستهلك هذه الدالة، لا حسابات يدوية في أي مكان.

## 4) انعكاس النتائج في الواجهات

| الواجهة | ما يتغيّر |
|---|---|
| `ShipmentForm` (التاجر) | بطاقة معلومات شركة الشحن: تعرض السياسة (عدد المحاولات، مهلة، رسم COD، رسم إرجاع، ملاحظات) قبل التأكيد |
| `MerchantShipments` | عمود "محاولات متبقية" + شارة "تجاوز SLA" بناءً على `delivery_sla_hours` |
| `MerchantWallet` | تفصيل المعاملة يُظهر: أجرة الشحن + رسم COD (إن كان على التاجر) — قيم محسوبة من المحرك |
| `CourierWalletPanel` | يُظهر `courier_payout` فقط (لا يرى هامش المنصة) |
| `ShipmentTable` (الأدمن) | عمود إضافي يفصّل الأرباح والرسوم لكل شحنة |
| منطق الإرجاع في `process-shipment-delivery` | يستخدم `return_fee_type/value/fixed` ويسجّل `wallet_transaction` للخصم |
| منطق محاولات التسليم | عند تجاوز `max_delivery_attempts` تنتقل تلقائياً إلى `returned` |

## 5) ضمانات (لا تعطيل لأي شيء قائم)

- **لا تغيير في الأدوار أو المسارات** — كل شيء داخل صفحة الشركاء الموجودة
- **القيم الافتراضية** على الحقول الجديدة تضمن أن الشحنات الحالية تست
