## المشكلة

عند تسجيل تاجر جديد بالإيميل، طلب التسجيل ينجح (status=200, `user_repeated_signup`) لكن لا يصل إيميل التأكيد. السبب: **لا يوجد دومين بريد مهيأ للمشروع**، فبريد التأكيد الافتراضي من Lovable Cloud إما محدود جداً (rate-limited) أو محجوب، ولا يتم تخصيصه باسم "صلة".

الدومين `sila-sy.com` متصل كدومين مخصص للموقع، ويمكن استخدامه أيضاً لإرسال البريد.

## الخطة

### 1. إعداد دومين البريد `sila-sy.com`
- عرض حوار إعداد البريد للمستخدم لتفعيل `sila-sy.com` كمُرسِل بريد رسمي.
- بعد التفعيل، تُضاف سجلات DNS تلقائياً (أو يدوياً عند مزود الدومين) ويبدأ التحقق.

### 2. تجهيز قوالب البريد المخصصة (Auth Email Templates)
بعد تهيئة الدومين، نُولّد قوالب بريد العربية بهوية "صلة":
- `signup.tsx` — تأكيد إنشاء حساب التاجر (الأهم لمشكلتك الحالية).
- `recovery.tsx` — استعادة كلمة المرور.
- `magic-link.tsx`, `invite.tsx`, `email-change.tsx`, `reauthentication.tsx`.

كل قالب سيستخدم:
- ألوان "صلة" من `index.css` (الأزرق الداكن + البرتقالي `#FF8C00`).
- خط `Readex Pro` للعربية مع fallback آمن للبريد.
- اتجاه RTL، نسخة عربية احترافية تطابق نبرة المنصة.
- شعار "صلة" إن وُجد في `public/`.

### 3. نشر `auth-email-hook` Edge Function
نشر الدالة التي تستقبل أحداث Auth وتُرسل القوالب المخصصة عبر بنية البريد في Lovable Cloud.

### 4. تحقق
- زر معاينة قالب التأكيد من إعدادات البريد.
- بعد التحقق من DNS، أي تسجيل جديد يستلم إيميل تأكيد فوراً من `noreply@sila-sy.com` (أو ما يماثله).

### تفاصيل تقنية
- لا حاجة لمفتاح Resend أو خدمة خارجية — كل شيء عبر بنية Lovable Cloud المُدارة.
- إعدادات Auth الحالية تُبقي تأكيد البريد **مفعّلاً** (لا auto-confirm)، وهذا صحيح للتجار.
- بعد التحقق من DNS، تتوقف رسائل Supabase الافتراضية وتبدأ قوالب "صلة" المخصصة فوراً، دون تغيير في كود `Signup.tsx`.

### خارج النطاق
- تغيير منطق التسجيل أو شاشة `VerifyEmail`.
- إيميلات معاملاتية أخرى (طلبات/شحنات) — يمكن إضافتها لاحقاً عبر `send-transactional-email`.
